1. Головна суть: Чому React і що змінилося після 5-ї лаби?

Головна думка, яку треба сказати викладачу:
«У 5-й лабораторній ми писали окремо HTML-розмітку у файлі data/index.html, а в JavaScript вручну шукали елементи через document.getElementById і склеювали рядки через innerHTML (імперативний підхід). У React ми перейшли на декларативний підхід та синтаксис JSX: тепер розмітка та логіка компонента описані разом в одному файлі JavaScript, а оновленням DOM займається сам React через механізм Virtual DOM».
Критерій Як було в Лабі 3–5 (Vanilla JS) Як стало в Лабі 6 (React.js)
Файли верстки Окремий великий data/index.html зі структурою тегів. public/index.html містить лише <div id="root"></div>. Увесь HTML генерується в React.
Формування карток Склеювання шаблонних рядків items.map(h => `<div>...</div>`).join('') та innerHTML = .... Функціональний компонент <HelicopterCard helicopter={heli} />, який повертає JSX.
Поділ коду Глобальні скрипти (dom.js, main.js, api.js), які взаємодіють з глобальним DOM. Компонентна архітектура: кожен візуальний блок (Header, Sidebar, Card) — це окремий незалежний компонент у власному файлі.
Стилізація Окремі CSS файли, що підключалися через тег <link> в HTML. Модульний імпорт CSS безпосередньо у відповідний JS-файл компонента (import './Header.css').

3. Покроковий розбір коду (Що відбувається в кожному файлі)

3.1. Точка монтування: public/index.html та src/index.js

У public/index.html немає жодного нашого тегу, крім:

<div id="root"></div>

У src/index.js React підключається до цього контейнера:

import React from 'react';
import ReactDOM from 'react-dom/client';
import './index.css';
import App from './App';

// Створюємо корінь React 18 через новий метод createRoot
const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
Що сказати: ReactDOM.createRoot знаходить звичайний DOM-вузол з id="root" і бере над ним повний контроль. Метод render(<App />) перетворює дерево компонентів React на реальні DOM-вузли всередині цього блоку.

3.2. Головний компонент src/App.jsx та джерело даних

Дані про вертольоти зберігаються у src/data/helicopters.js (масив з 5 об'єктів з полями id, name, passengers, maxSpeed, description). Компонент App збирає всю сторінку:

3.3. Рендеринг списку: src/components/CardsGrid/CardsGrid.jsx

import React from 'react';
import HelicopterCard from '../HelicopterCard/HelicopterCard';
import './CardsGrid.css';

const CardsGrid = ({ helicopters = [] }) => {
  return (
    <section className="content">
      <div className="cards-grid" id="cards-grid">
        {helicopters.length === 0 ? (
          <div className="cards-empty">Вертольотів не знайдено.</div>
        ) : (
          /* Метод .map() перетворює кожен JS-об'єкт вертольота на JSX-компонент */
          helicopters.map((heli) => (
            <HelicopterCard key={heli.id} helicopter={heli} />
          ))
        )}
      </div>
    </section>
  );
};

export default CardsGrid;

4. ТОП-10 питань викладача на захисті та готові відповіді

Питання 1 Що таке JSX і чому браузер не може виконати його напряму?
Відповідь: JSX (JavaScript XML) — це розширення синтаксису JavaScript, яке дозволяє писати HTML-подібну розмітку безпосередньо у коді JS. Браузер не розуміє JSX напряму, тому транспілятор Babel (у складі react-scripts) перед виконанням перетворює JSX на стандартні виклики функцій React.createElement(...) або новий JSX runtime _jsx(...).
Питання 2 Чому замість class ми пишемо className, а замість for — htmlFor?
Відповідь: Оскільки JSX — це розширення мови JavaScript, слова class та for є зарезервованими ключовими словами у JS (для оголошення класів та циклів). Щоб уникнути синтаксичного конфлікту, у React для HTML-атрибутів використовуються відповідні DOM-властивості: className та htmlFor.
Питання 3 Що таке Функціональні Компоненти (Functional Components)? Чим вони кращі за класові?
Відповідь: Функціональний компонент — це звичайна JS-функція, яка приймає вхідні дані (props) і повертає JSX. Вони є сучасним стандартом React (починаючи з версії 16.8), оскільки мають значно простіший та лаконічніший синтаксис, не потребують ключового слова this, займають менше пам'яті та легко використовують React Hooks (useState, useEffect).
Питання 4 Що таке Props (пропси) і яке правило їх зміни в React?
Відповідь: Props (properties) — це вхідні параметри, які передаються від батьківського компонента до дочірнього (наприклад, <CardsGrid helicopters={INITIAL_HELICOPTERS} />).
Важливе правило: Props є read-only (незмінними)! Дочірній компонент ніколи не повинен мутувати (змінювати) свої пропси напряму, оскільки React підтримує строгий односторонній потік даних (One-Way Data Flow).
Питання 5 Навіщо обов'язково вказувати key={heli.id} у циклі map()?
Відповідь: Ключ key — це унікальний ідентифікатор елемента списку, який потрібен алгоритму узгодження React (Reconciliation / Virtual DOM diffing). Завдяки key React точно знає, яка саме картка була додана, змінена чи видалена, і оновлює в реальному браузері лише цей конкретний вузол, а не перемальовує весь список заново.
Питання 6 Що таке Virtual DOM (Віртуальний DOM) і як він працює?
Відповідь: Virtual DOM — це легка копія реального дерева DOM у пам'яті (у вигляді простих JS-об'єктів). Коли змінюються дані:
  1. React будує нове дерево Virtual DOM.
  2. Порівнює його зі старим деревом (процес Diffing).
  3. Знаходить мінімальну необхідну різницю та точково вносить зміни в реальний браузерний DOM (процес Reconciliation). Це на порядки швидше за пряме перезаписування innerHTML.
Питання 7 Чому в index.html нічого немає, а сайт відображається?
Відповідь: Тому що це архітектура Single Page Application (SPA). Браузер завантажує порожній скелет сторінки з єдиним тегом <div id="root"> і скрипт збірки React. Скрипт виконується на клієнті і за допомогою ReactDOM.createRoot().render(<App />) повністю формує весь HTML і вставляє його в root.
Питання 8 Як передаються стилі компонентів у нашому додатку?
Відповідь: Кожен компонент має свій окремий CSS-файл (наприклад, Header.css, Sidebar.css, CardsGrid.css), який імпортується безпосередньо у відповідний файл компонента через команду import './Header.css'. Під час збірки Webpack збирає ці стилі в єдиний оптимізований бандл.
Питання 9 Які дані представляє наша сутність (Варіант 8)?
Відповідь: Сутність — Helicopter (Вертоліт). Поля об'єкта відповідають попереднім роботам: id (число), name (назва вертольота, рядок), passengers (кількість пасажирських місць, число), maxSpeed (максимальна швидкість у км/год, число), description (опис призначення).
Питання 10 Чому кнопки Edit, Remove та Search зараз не виконують дії?
Відповідь: Згідно з технічним завданням 6-ї лабораторної роботи, вимагається реалізувати виключно представлення сторінки (View-only part): перенести розмітку в компоненти React і налаштувати стилі. Вся інтерактивність (useState, фільтрація, роутинг, редагування через форми та робота з API) запланована на наступні лабораторні роботи (7–8).
